# Admin Application UI Profile

## Objective

Design predictable, sober, information-oriented interfaces for dashboards,
CRUDs, forms, tables, filters, navigation, reusable application components,
and daily operational workflows.

## Direction

- Prioritize task completion, legibility, scanning, and consistency.
- Prefer established application patterns over novelty.
- Let information hierarchy determine layout and density.
- Use restrained spacing, radius, shadows, decoration, and color.
- Prefer tables and lists for structured records.
- Use cards only when independent grouping is meaningful.
- Keep primary, secondary, and destructive actions clearly differentiated.
- Use motion primarily to communicate state, continuity, or feedback.
- Avoid decorative gradients, effects, and animations that compete with work.
- Preserve the active theme and consume its semantic tokens.

## Required workflow

1. Load every skill listed in `required-skills`.
2. Inspect the affected UI and its closest project equivalents.
3. Apply the active theme and existing component contracts.
4. Use `admin-interface-design` to choose information and interaction patterns.
5. Use `shadcn` to implement or review component composition correctly.

## Review

Use the rendered-review guidance from `admin-interface-design`. Verify the
relevant states, responsive widths, color modes, and comparable interfaces.
